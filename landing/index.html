Teams need more than a private chat window.

  1. Work gets stuck in private chats

    Everyone has their own ChatGPT tab. The team doesn't share agents, memory, or control, so the same context gets pasted in again every day.

  2. Agent tools are built for one operator

    Tools like OpenClaw and Hermes Agent are capable, but they run on one machine for one person. Teams and agencies need users, clients, roles, and channels.

  3. Nakama is one agent workspace for the whole team

    One server, many orgs. Invites and roles. Agents isolated from each other. Set it up with managed cloud or one Docker container.

01 · The dashboard

Feels like ChatGPT. Works like a team.

Pick an agent, chat, and check its work. Organizations, profiles, automations, and integrations are one click away in the same sidebar.

02 · How it works

Give an agent a soul, a toolbox, and a place to talk.

  1. A

    Define the agent

    Each profile is a set of plain files. The agent keeps context across sessions, and org memory grows over time.

    • SOUL.mdidentity
    • STYLE.mdvoice
    • INSTRUCTIONS.mdrules
    • MEMORY.mdfacts

  2. B

    Give it capabilities

    Assign tools, skills, and MCP servers per profile. Connect external apps through Composio.

    • Built-in tools
    • Skills
    • MCP
    • Composio · 1,000+ apps
    • Plugins

  3. C

    Meet the team where it works

    The same agent, with the same soul, answers on every channel. Automations deliver results on a schedule.

    • Web
    • CLI
    • Telegram
    • WhatsApp
    • Discord
    • Slack

03 · Capabilities

Built for teams from day one.

Automations that report back

Schedule agent work on a timer and send results to Telegram, WhatsApp, or Discord. A daily standup digest posts itself; your team reads it over coffee.

Agent work → Automations → Send results to

Organizations & roles
Orgs are tenants. Invite people as admin, member, or viewer. Profiles, sessions, automations, tools, and usage stay isolated per org.
Souls & memory
Identity, voice, rules, and memory live in files you can read and edit. Profiles can move between organizations.
Skills that get reviewed
Agents can turn successful work into reusable skills. Skills keep a version history, and member-written skill code waits for an admin review.
Tools, MCP & Composio
Built-in tools, your own MCP servers, and more than 1,000 external apps through Composio. Assign them per profile with /add-tool and /add-mcp.
Coding agents
Start Codex, Claude Code, OpenCode, or Cursor Agent from a chat to write and change code, including Nakama itself.
Plugins
Bundled plugins add workflows, Supermemory, and Google Meet. Build your own for what your team needs.
Bring your model
Connect the provider you already pay for, including OpenRouter, Mistral, Together AI, Moonshot Kimi, and ChatGPT Plus/Pro through Codex OAuth. See usage and cost per reply.
Web, CLI & desktop
A web dashboard, a terminal client, and a macOS desktop app, all thin clients of one server with interactive API docs at /docs.

05 · Deploy

Running in minutes. On our servers or yours.

Self-host it like WordPress, or let Nakama Cloud handle hosting. Either way, a setup wizard asks for your provider and API key on first run.

  • ~200 MB idle. 1 vCPU and 1 GB is enough for the server on its own.
  • One container. Data in a single volume, dashboard on port 4310.

The least work. No Bun, Docker, or VPS needed.

  1. Create an account.
  2. Provision an instance.
  3. Finish the setup wizard in the browser.
Try Nakama Cloud →

Prebuilt image, one container.

# Pull and run the latest image
docker pull ghcr.io/ahmadrosid/nakama:latest
docker run -d -p 4310:4310 \
  -v nakama-data:/nakama/data \
  --name nakama ghcr.io/ahmadrosid/nakama:latest

Then open http://localhost:4310. Check the requirements before enabling channel workers.

From source, with Bun.

git clone https://github.com/ahmadrosid/nakama.git
cd nakama
bun install
bun run dev:web

The web dashboard opens at http://localhost:3003 and starts the server if needed.
